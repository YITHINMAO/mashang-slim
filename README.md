# 码上瘦身

码上瘦身是一个本地离线的视频转码瘦身桌面工具，支持拖入单个视频、多个视频或文件夹，批量输出 MP4 / MOV / MKV，并在完成后标注格式、路径、色深、分辨率和体积变化。

最新安装包下载见 GitHub Releases：https://github.com/YITHINMAO/mashang-slim/releases

## 成品包

- macOS Apple Silicon：`release/码上瘦身-0.1.5-arm64.dmg`
- Windows x64 安装版：`release/码上瘦身-Windows-x64-安装版.zip`
- Windows x64 便携版：`release/码上瘦身-Windows-x64-便携版.zip`，解压后直接运行单文件便携版 exe

## 功能

- H.264 / H.265 输出到 MP4、MOV、MKV
- H.265 默认按更低目标码率推荐，体现同等观感下的体积优势
- 支持预设码率、自定义码率和连续码率滑杆
- 拖入后按当前设置预估输出体积，单位统一为 MB
- 多任务队列处理，默认并发 2 个任务，可在设置里调整
- 支持暂停/继续队列，正在处理的任务也会暂停
- 默认启用硬件加速：macOS 使用 Apple VideoToolbox，Windows 自动探测 NVIDIA / Intel / AMD 硬件编码器
- 硬件加速、硬件模式和语言切换已收纳到独立设置面板，首页只保留常用转码选项
- 硬件编码器不可用或不支持当前位深时，会自动回退软件编码
- 自动读取分辨率、帧率、文件大小、像素格式、位深
- 显示当前任务预计完成时间、整个队列预计完成时间和完成后的总耗时
- 输出时保持原视频位深和分辨率，转码完成后再次用 `ffprobe` 验证
- 音频默认自动兼容：容器支持时复制原轨，不支持时自动转 AAC 192k
- 可手动开启保守模式，让输出目标码率不低于源视频码率
- macOS / Windows 打包版内置 `ffmpeg` 和 `ffprobe`，双击 App 不依赖终端 PATH
- 支持中文 / English 界面切换

如果内置编码器不支持保持输入位深，应用会阻止开始转码，而不是静默降级到 8-bit。

## Mac 配置建议

当前 Mac 包是 Apple Silicon arm64 版本，适合 M1、M2、M3、M4 系列 Mac。Intel Mac 需要单独打 x64 包。

最低配置：

- macOS 12 或更新版本
- Apple M1
- 8 GB 内存
- 至少预留源视频 2 倍以上的可用磁盘空间

推荐配置：

- Apple M2 / M3 / M4，Pro / Max 更适合 4K 批量处理
- 16 GB 或更高内存
- SSD 剩余空间 50 GB 以上
- 4K 或 10-bit 视频建议并发 1 个任务；1080p 可使用默认并发 2 个任务
- 默认硬件加速会明显降低 CPU 压力；如遇兼容问题可在高级设置中关闭

预估性能：

- 1080p H.265 `均衡`：硬件加速常见约 2x 到 8x 实时速度，软件编码约 0.6x 到 2x
- 4K H.265 8-bit `均衡`：硬件加速常见约 0.8x 到 3x，软件编码约 0.25x 到 0.8x
- 4K H.265 10-bit `均衡`：硬件加速常见约 0.6x 到 2x，软件编码约 0.15x 到 0.5x
- 选择 `快` 或 `很快` 会明显提速，但同体积下画质会略低

## Windows 配置建议

当前 Windows 包是 x64 版本，适合 Windows 10 / Windows 11 64 位系统。

最低配置：

- Windows 10 64 位或更新版本
- Intel Core i5 / AMD Ryzen 5 级别 CPU
- 8 GB 内存
- 至少预留源视频 2 倍以上的可用磁盘空间

推荐配置：

- Intel Core i7 / i9 或 AMD Ryzen 7 / 9
- 16 GB 或更高内存
- SSD 剩余空间 50 GB 以上
- 4K 或 10-bit 视频建议并发 1 个任务；1080p 可使用默认并发 2 个任务
- 默认硬件加速会优先使用可用 GPU 编码器；如果驱动或显卡不支持，会自动回退软件编码

预估性能：

- 1080p H.265 `均衡`：硬件加速常见约 1.5x 到 8x 实时速度，软件编码约 0.4x 到 1.5x
- 4K H.265 8-bit `均衡`：硬件加速常见约 0.6x 到 3x，软件编码约 0.15x 到 0.6x
- 4K H.265 10-bit `均衡`：硬件加速常见约 0.4x 到 2x，软件编码约 0.08x 到 0.4x
- 速度主要取决于 CPU 核心数、散热和源视频复杂度

## 使用建议

- 默认输出格式建议使用 MP4，编码建议使用 H.265。
- 默认质量建议先用 `推荐`，想进一步压小再试 `轻巧`。
- 4K、10-bit、DJI、相机素材建议把并发上限设为 1。
- 微信、手机、1080p 视频通常可以保持默认并发 2。
- 如果必须保留原音轨，可以选择 `强制保留原轨`；如果输出 MP4 失败，改回 `自动兼容`。

## 开发运行

```bash
npm install
npm start
```

开发运行时会优先使用 `vendor/ffmpeg/<平台>` 内置工具；如果没有内置工具，才会读取系统 `ffmpeg` 和 `ffprobe`。

## 打包

```bash
npm run package:mac
npm run package:win
```
